# Sentinel — Architecture (SIH 26153 / NTRO)

## 1 · Problem & gap
Enterprise and Critical Information Infrastructure defenders must see an
intrusion **coming**, not confirm it after impact. Conventional ML IDS map each
flow to a benign/malicious label in isolation — `P(attack | flow)` — discarding
the temporal/causal structure of an infiltration (the order of port probes, SYN
timing before floods, reconnaissance cadence before lateral movement) and
collapsing on attack stages absent from training. On our chronological CIC-IDS2018
hold-out, at a 5% false-positive budget, the single-window logistic-regression
baseline scores **F1 0.245 / recall 0.144 / ROC-AUC 0.814** — it misses infiltration
that only reveals itself as a *sequence* over time.

## 2 · World-model approach
Sentinel learns the **transition dynamics** `P(Sₜ₊₁ | Sₜ,…,S₋w)` of the network
state and simulates forward. This is a world model, not a classifier: it reads the
8-window history and predicts the *next state* and next-window attack probability.
Result on the same real hold-out, same 5% FPR budget (21-feature set): **F1 0.664
/ recall 0.606 / ROC-AUC 0.802 / PR-AUC 0.683**, catching **61%** of infiltration
windows vs the baseline's **14%** (a 4.5× recall gain), and raising a sustained
alarm **+20 s (2 windows) earlier**. Ranking metrics (ROC-AUC/PR-AUC) are ~tied with the
baseline; the world model's decisive advantage is at the operating point.

## 3 · Data pipeline (`pipeline/`)
```
flow CSV / PCAP → schema auto-detect (CIC-IDS 2017/2018, UNSW-NB15, CTU-13/Zeek, CICIoT, NetFlow)
 → 21-dim network-state feature vector per flow window (flow + packet level):
    flow_count, uniq_dst_ports/ips, syn/synAck/rst/fin ratios, avg bytes/pkts/dur,
    iat_mean/var, port_scan_score, failed_conn_ratio, lateral_score,
    bytes_out_ratio, ttl_var, retrans_ratio,
    win_mean (TCP window), frag_ratio (IP fragment flags), payload_var (payload dist)
 → chronological 10 s windows  → state sequence S₁…S_N
```
Training data: **CSE-CIC-IDS2018, Thursday-01-03-2018** (Infiltration day), 331,100
labelled CICFlowMeter flows, 28% Infiltration → 3,407 windows.
PCAP is aggregated into the same 5-tuple flow schema by a dependency-free
classic-libpcap parser (scapy fallback for pcapng). Windows preserve time order;
train/test splits are **temporal**, never shuffled — no leakage.
Ground-truth stage labels come from dataset annotations via
`config/mitre_mapping.yaml` (inspectable, not hardcoded).

### Data provenance (explicit)
- **Model training + benchmark:** real **CSE-CIC-IDS2018** Infiltration-day CSV
  (`data/raw/cicids2018_thu01mar.csv`, obtained via `scripts/download_dataset.sh`).
  The headline metrics (world F1 0.664 vs baseline 0.230, recall 0.606 vs 0.135) are
  measured on its held-out temporal test split — genuinely real numbers.
- **In-app "Run demo capture":** a **synthetic** infiltration trace
  (`data/demo_capture.csv`, generated by `pipeline/synth.py`) in CIC-IDS flow
  schema, used only to demonstrate the inference path offline without shipping the
  108 MB corpus. The UI labels it "Synthetic infiltration capture · CIC-IDS schema".
  Uploading a real flow CSV/PCAP runs the same trained model on real data.

### Packet-level features (all PS-required fields implemented)
The 21-d vector combines flow-level and packet-level features. Raw **PCAP** is
parsed **dependency-free** (`backend/runner.py`: a classic-libpcap reader in pure
Python; scapy is a fallback for pcapng / exotic link types), so packet fields come
from real packets when a `.pcap` is uploaded, or from CIC-style columns when a flow
CSV already carries them (e.g. `Init Fwd Win Byts`, `sTtl`).
- **TTL value/variance** → `ttl_var` (std of per-flow TTL in the window).
- **TCP window size** → `win_mean` (mean of per-flow TCP window; from PCAP or the
  `Init Win Bytes Forward` column).
- **IP fragment flags** → `frag_ratio` (fraction of flows with the More-Fragments
  bit or a non-zero fragment offset; extracted from the IP header in PCAP).
- **Payload size distribution** → `payload_var` (std of per-flow mean payload =
  bytes/packets across the window).
- **Port-scan signatures** → `port_scan_score` (dst-port breadth + sequentiality).
- **Retransmission counts** → `retrans_ratio` (duplicate data-segment TCP seq).
All six PS-required packet-level features are computed and fed to the model.

## 4 · State representation
Each window → a standardised 21-d vector `Sₜ`. Supervised stage labels map to
kill-chain phases: benign, reconnaissance, initial access, lateral movement,
command & control, exfiltration.

## 5 · World model (`models/world_model.py`)
Single-layer **LSTM** with **full BPTT + Adam**, NumPy only (Torch omitted for
disk; gradients numerically verified, max rel error ≈1e-7). A sequence of `w`
windows is encoded to a latent state `h_T`; two heads sit on it:
- **next-state head** `Sₜ₊₁ = f(h_T)` — trained with MSE. *These are the learned dynamics.*
- **stage head** — softmax over ATT&CK stages (cross-entropy).

**Transition dynamics choice — LSTM vs Transformer/GNN:** on the small labelled
regime an LSTM trains stably and its next-state error is a clean novelty signal;
a Transformer encoder and a temporal GNN over the host graph are drop-in upgrades
(the pipeline interface is encoder-agnostic).

## 6 · Forecasting & detection
- **K-step rollout:** feed each predicted `Sₜ₊₁` back in, `w`-step autoregressive
  simulation; per horizon, the stage head gives the attack-stage distribution and
  the infiltration-probability curve.
- **Detection = the trained temporal stage head.** The world-model score is
  `1 − P(benign | last w windows)` — a predictor over the *sequence* of network
  states, which is where its measured lift over the single-window baseline comes
  from (F1 0.664 vs 0.230, recall 0.606 vs 0.135 at the same operating point;
  ROC-AUC is ~tied). Standardized inputs are **clipped** and near-constant feature
  stds are **floored** so an out-of-distribution capture cannot saturate the model
  into a false alarm. A transition-surprise **novelty** channel (the
  model's own next-state reconstruction error, calibrated on benign training
  dynamics) is computed as an auxiliary unsupervised anomaly signal; on this
  dataset it does not beat the supervised temporal predictor and is reported
  honestly as auxiliary, not the headline.

## 7 · MITRE ATT&CK mapping
An **evidence-based** layer (`backend/infer.py`) maps a state's real feature
signature to a stage via ordered kill-chain rules (broad sequential dst-port
access → Reconnaissance; unanswered SYN + SYN/ACK anomaly → Initial Access;
internal fan-out → Lateral Movement; outbound byte skew → Exfiltration). On small
data this is the authority for the displayed stage; the LSTM stage head is a weak
prior. Techniques (T1595, T1046, T1021, T1041…) are indicative references.

## 8 · Explainability
Real gradients through the LSTM: **grad×input** per feature (signed contribution)
and **temporal saliency** — the per-window gradient magnitude from the same
backprop. Displayed z-scores use the robust (floored) std and are clipped to ±8,
so a near-constant training feature can never render an absurd value. No black-box
output.

## 9 · Evaluation methodology
**Chronological split** (train = first 65% of the timeline, test = last 35%;
2,209 / 1,190 sequences) — the model is tested on strictly *later* traffic, so
there is no temporal leakage. Both models fit on train only; operating thresholds
set at a fixed **5% FPR on training predictions** (never tuned on test), the
security-relevant "equal false-alarm budget" comparison. Metrics: P/R/F1, ROC-AUC
(sklearn), PR-AUC, FPR, confusion matrices, forecast lead time. `python train.py`
regenerates `models/benchmark.json` bit-for-bit; a test asserts the served figures
equal a fresh evaluation — the UI cannot show stale/invented numbers.

## 10 · Deployment
`backend/` FastAPI, fully offline (loads local weights, no outbound calls) — the
required offline demo. The **deployed** site (Vercel) serves precomputed **real**
model output (`public/real/*.json`) for the demo and benchmark and calls a
same-origin **Vercel Python function** (`api/index.py`, in-process inference) for
live uploads; if unreachable it falls back to the precomputed real output, and
custom uploads fall back to an in-browser engine. `docker compose up` runs the
whole stack offline. The dashboard has a light (default) / dark theme toggle.

## 11 · Threat model
**Trusts:** the local operator and the host filesystem. **Does not trust:**
uploaded captures. An uploaded PCAP/CSV may be malformed or **adversarial**:
(a) *crafted to crash/hang the parser* — mitigated by an allowlist, a 25 MB cap,
UUID-scoped temp paths (never the client filename), and running parse+inference
in an **isolated subprocess with a timeout**, so a crash/hang fails one request,
not the service; (b) *crafted to evade the model* (adversarial perturbation of
flow statistics, or mimicry of benign dynamics) — **not solved**; the novelty
channel raises the bar for stealth but adversarial robustness is acknowledged
future work, not a claim. No uploaded data leaves the host (no telemetry); CORS
is locked to the dashboard origin; dependencies are pinned and audited (0 vulns).
